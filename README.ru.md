# compxctl

**Переключение частоты опроса (polling rate) мышей CompX / Ardor Gaming в Linux — 125, 500 или 1000 Гц — через проприетарный HID-протокол, которым пользуется только Windows-софт вендора.**

Мыши CompX / Ardor Gaming хранят частоту опроса в прошивке самого чипа мыши, но производитель выпускает программу настройки только для Windows. Официального Linux-инструмента нет. `compxctl` — результат реверс-инжиниринга этого протокола: CLI из одного Python-файла, который повторяет перехваченные управляющие отчёты и переключает частоту на самом устройстве — включая запись в EEPROM, чтобы настройка переживала переподключение. Встроенная команда `check` затем доказывает результат, замеряя фактическую частоту по событиям ввода.

```bash
python3 compxctl.py set 1000   # применить 1000 Гц сейчас; частота переживёт переподключение
python3 compxctl.py check      # проверка: пошевелите мышью ~1,5 секунды, пока идёт замер
```

Никаких демонов, GUI и модулей ядра. Root нужен один раз — для установки udev-правил.

---

## Зачем это нужно

Мыши этого семейства настраиваются через проприетарный USB-протокол, который понимает только Windows-утилита вендора. В Linux выбор был плохим:

- оставаться на той частоте, с которой мышь пришла или которую задали в последний раз под Windows;
- загружать Windows (или VM с пробросом USB) каждый раз, когда нужно переключиться;
- мириться с 125 Гц, если мышь по умолчанию работает на ней, — серьёзный минус для соревновательного гейминга.

Сам протокол небольшой и стабильный: каждая частота — это последовательность из трёх HID-отчётов, отправляемых в конфигурационный интерфейс мыши. Как только эти отчёты были распознаны, переключение частоты превратилось в вопрос повторной отправки байтов, а не эмуляции драйвера. `compxctl` упаковывает это в две команды: `set` — применить частоту, `check` — замерить фактическую.

## Поддерживаемое железо

Целевое семейство — CompX / Ardor Gaming, USB vendor ID `0x25A7`:

| PID      | Железо | Как определяется на шине |
|----------|--------|--------------------------|
| `0xFA7B` | Проводная мышь | В `lsusb` определяется как *Dual Mode Mouse* |
| `0xFA7C` | Приёмник 2.4 ГГц (донгл) | `Areson Technology Corp 2.4G Wireless Receiver` |
| `0xFA03`, `0xFA93` | Другие устройства того же семейства | Распознаются по тому же списку VID/PID |

```console
$ lsusb -d 25a7:
Bus 001 Device 003: ID 25a7:fa7c Areson Technology Corp 2.4G Wireless Receiver
```

Протокол был перехвачен на **Ardor Gaming Ulta** (бренд Compx). Остальные PID относятся к тому же семейству и обслуживаются тем же кодом, но индивидуально не проверялись.

Для `check` узлы ввода мыши находятся по фиксированным by-id-именам:

- `/dev/input/by-id/usb-Compx_2.4G_Wireless_Receiver-event-mouse`
- `/dev/input/by-id/usb-Compx_2.4G_Dual_Mode_Mouse-event-mouse`

с запасным вариантом — сканированием `/dev/input/event*` через sysfs по vendor/product.

## Как это работает

### Протокол: три отчёта на частоту

Переключение происходит на уровне чипа через конфигурационный HID-интерфейс мыши (vendor usage pages `0xFF01`–`0xFF04`, запасной вариант — интерфейс №1). Каждая частота — ровно три отчёта: первые два применяют частоту «на лету», третий записывает её в EEPROM, чтобы она пережила отключение и повторное подключение.

| Частота | ① частота — отчёт `0x06`        | ② интервал — отчёт `0x08` / `0x11`  | ③ сохранение — отчёт `0x08` / `0x07` |
|---------|---------------------------------|-------------------------------------|--------------------------------------|
| 125 Гц  | `06 11 00 00 00 00 00 00`       | `08 11 00 00 00 06 08 …`            | `08 07 00 00 00 06 08 …`             |
| 500 Гц  | `06 11 00 01 00 00 00 00`       | `08 11 00 00 00 06 02 …`            | `08 07 00 00 00 06 02 …`             |
| 1000 Гц | `06 11 00 02 00 00 00 00`       | `08 11 00 00 00 06 01 …`            | `08 07 00 00 00 06 01 …`             |

(`…` — фиксированная часть вендорского пакета, воспроизводится байт-в-байт, как была перехвачена.)

Что означают переменные байты:

- ① байт 3 отчёта (с нуля, с учётом байта report id) — **код частоты**: `0x00` → 125 Гц, `0x01` → 500 Гц, `0x02` → 1000 Гц;
- ② байт 6 — **интервал отчёта в миллисекундах**: `0x08` → 8 мс → 125 Гц, `0x02` → 2 мс → 500 Гц, `0x01` → 1 мс → 1000 Гц;
- ③ несёт тот же байт интервала, но это **запись в EEPROM** — именно она делает частоту «липкой» при отключении питания. Хвостовые байты пакета меняются вместе с частотой и не пересчитываются — они воспроизводятся точно так, как были перехвачены.

Вся таблица живёт в одном месте кода — `POLLING_VARIANTS` — так что определение протокола имеет единственный источник истины.

### Избыточная доставка

Мышь никогда не подтверждает отчёты, а конфигурационный интерфейс капризен в вопросах владения драйвером ядра. Поэтому `compxctl` не доверяет одному каналу. Каждый из трёх отчётов отправляется по нескольким независимым каналам:

1. **USB control transfer** (pyusb/libusb): feature `SET_REPORT` на интерфейс 1, с отсоединением драйвера ядра на время передачи и немедленным возвратом;
2. **hidapi**: сначала `send_feature_report`, затем обычный output `write` на том же дескрипторе;
3. **сырой hidraw ioctl**: `HIDIOCSFEATURE` / `HIDIOCSOUTPUT` — последний запасной путь в обход hidapi.

Отправки кратко повторяются: после того как pyusb-шаг отсоединил и вернул драйвер ядра, udev заново создаёт hidraw-узел, и он может быть мгновение недоступен.

Смена частоты считается успешной, когда доставлено **не менее 2 из 3 пакетов** (`Packets sent: N (minimum for success: 2)`). Если подключено несколько поддерживаемых устройств, новый режим получает каждый найденный управляющий путь.

Честная оговорка: устройство не шлёт подтверждений. «Успех» означает, что пакеты доставлены, а не что чип их подтвердил — именно для этого нужна команда `check`.

### Что замеряет `check`

`check` не разговаривает с чипом. Он открывает узел ввода мыши и считает события относительного движения (`EV_REL`) в течение ~1,5 секунды, пока вы шевелите мышью:

```text
Event device: /dev/input/eventN
Move the mouse… measuring for ~1.5 s
Measured rate: ~1000 Hz
```

Частота — это количество событий, делённое на окно замера: практическая, честная проверка, а не лабораторный прибор.

## Требования и установка

Требования:

- Linux и Python 3;
- `hidapi` — поиск устройства и основной канал отправки отчётов (нужен для `set`);
- `pyusb` — запасной канал прямого USB `SET_REPORT` (рекомендуется; без него утилита всё равно работает через hidapi и печатает предупреждение);
- `evdev` — подсчёт событий, нужен только для `check`.

```bash
pip install -r requirements.txt
```

Из-под root утилита работает без каких-либо udev-правил. Для обычных пользователей один раз установите правила доступа:

```bash
sudo cp 99-compx-mouse.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger
```

Затем переподключите мышь (подойдёт и повторный вход в систему). Файл правил выдаёт доступ:

| Тип узла | Доступ |
|----------|--------|
| `hidraw` (канал управления в `set`) | группа `users`, режим `0660`, плюс `TAG+="uaccess"` для активной logind-сессии |
| `input` (читается командой `check`) | группа `input`, режим `0660`, плюс `TAG+="uaccess"` |
| `usb`-узел устройства (запасной канал pyusb) | группа `users`, режим `0664` |

`TAG+="uaccess"` покрывает обычную desktop-сессию (logind) без лишних действий. Для SSH-сессий или систем без logind добавьте себя в обе группы и перелогиньтесь:

```bash
sudo usermod -aG users,input $USER
```

Проверьте установку:

```console
$ python3 compxctl.py --version
compxctl 1.0.0
```

## Использование

Вывод утилиты — на английском; ниже приведены реальные строки программы.

### `set` — применить частоту

```console
$ python3 compxctl.py set 1000
Rate: 1000 Hz
PID: 0xfa7b
Packets sent: 6 (minimum for success: 2)
EEPROM write: done
```

Что означает вывод:

- `Rate` — запрошенная частота;
- `PID` — идентификатор устройства, найденного на шине;
- `Packets sent` — успешные доставки по всем каналам; точное число зависит от того, сколько каналов сработало, успех — от `>= 2`;
- `EEPROM write` — `done`, когда пакет сохранения ушёл; `not confirmed (rate may reset after re-plug)`, если нет.

Некритичные проблемы печатаются в stderr строками `warning: …` и не прерывают команду — например, `warning: usb: pyusb is not installed (pip install pyusb)`, если запасной канал недоступен. Если устройство отвергло пакеты, команда завершается ошибкой `Error: the device rejected the polling-rate packets`, за которой идёт по строке на каждый отказавший канал (с отступом).

### `check` — замерить фактическую частоту

```console
$ python3 compxctl.py check
Event device: /dev/input/event9
Move the mouse… measuring for ~1.5 s
Measured rate: ~1000 Hz
```

Шевелите мышью всё окно замера. Если она стоит на месте, вы получите честный ноль:

```console
$ python3 compxctl.py check
Event device: /dev/input/event9
Move the mouse… measuring for ~1.5 s
Measured rate: ~0 Hz (no mouse movement detected during the window)
Hint: keep moving the mouse while `check` runs.
```

Автоопределение использует by-id-имена из списка выше, затем sysfs-сканирование. Если нужен конкретный узел, укажите его явно: `python3 compxctl.py check --device /dev/input/eventN`.

### Коды возврата

| Код | Значение |
|-----|----------|
| `0`  | успех (включая легитимный замер `~0 Hz`) |
| `1`  | ошибка — устройство не найдено, проблемы с правами, пакеты отвергнуты |
| `130` | прервано по Ctrl+C |

### Одна команда вместо трёх слов

Утилита — один самодостаточный файл, поэтому её можно положить куда угодно и завести алиасы. Для fish:

```fish
# ~/.config/fish/config.fish — подставьте путь к вашей копии
alias 1000 "python3 ~/compx-control/compxctl.py set 1000"
alias 500  "python3 ~/compx-control/compxctl.py set 500"
alias 125  "python3 ~/compx-control/compxctl.py set 125"
```

Перезапустите шелл — и простой ввод `1000` переключит мышь. Тот же приём работает в bash/zsh с одинарными кавычками.

## Нештатные ситуации (troubleshooting)

| Симптом (как печатает программа) | Вероятная причина | Решение |
|----------------------------------|-------------------|---------|
| `Error: No CompX mouse found (VID 0x25A7). Check the USB connection: lsusb -d 25a7:` | Мышь не подключена или не определилась | Выполните `lsusb -d 25a7:`; переподключите мышь / переставьте приёмник; попробуйте другой USB-порт |
| `No access to the HID device. Reinstall the udev rules (99-compx-mouse.rules) and re-plug the mouse.` | Отсутствуют/устарели udev-правила или членство в группах (сторона `set`) | Повторите установку udev-правил, переподключите мышь, убедитесь, что вы в группах `users` и `input`, перелогиньтесь |
| `No read access to /dev/input/…` в `check` | Нет группы `input` / нет `uaccess` для сессии | `sudo usermod -aG input $USER` + повторный вход; проверьте `TAG+="uaccess"` в правилах |
| `Measured rate: ~0 Hz (no mouse movement detected during the window)` | Мышь не двигалась во время замера | Запустите `check` ещё раз и шевелите мышью все ~1,5 секунды |
| `Error: the device rejected the polling-rate packets` + строки каналов с отступом | Не сработал ни один канал | Читайте строки с отступом — каждая называет свой канал (`usb:`, `feature:`, `output:`, …); один раз попробуйте `sudo python3 compxctl.py set …`, чтобы исключить права; переподключите мышь и повторите |
| Код `0`, но `warning: usb: pyusb is not installed …` | Не установлен запасной канал pyusb | Установите (`pip install pyusb`) — либо игнорируйте, если `EEPROM write: done` |

## Известные ограничения

Честно о том, чем этот инструмент является, а чем нет:

- **Привязан к вендору по дизайну.** Затрагиваются только устройства VID `0x25A7` из списка PID — а значит, другие мыши для него полностью безопасны.
- **Экспериментальный протокол.** Перехвачен на одном устройстве (Ardor Gaming Ulta, бренд Compx). Соседние PID обслуживаются одинаково, но индивидуально не проверялись; будущая ревизия прошивки может изменить отчёты.
- **Нет подтверждения от устройства.** Успех означает доставку пакетов; за истину принимайте `check`.
- **Запись в EEPROM при каждом переключении.** Пакет сохранения переписывает EEPROM мыши на каждом запуске. Ресурс записи конечен, но при переключении несколько раз в день это некритично.
- **`check` — практическая оценка**, а не лабораторный замер: окно ~1,5 секунды, движение задаёт человек.

```
compxctl/
├── compxctl.py            # весь CLI: поиск, каналы, таблица протокола
├── 99-compx-mouse.rules   # udev-доступ к узлам hidraw / input / usb
├── requirements.txt       # hidapi, pyusb (опциональный канал), evdev (только check)
├── README.md              # английская версия
└── README.ru.md           # этот файл
```

Небольшое замечание о дизайне: проект консолидировался намеренно. Ранние прототипы — GUI плюс обслуживающие скрипты — разносили логику по `main.py`, `set-rate.py` и `auto-scan.py` (удалены), и каждый хранил собственную копию таблицы пакетов; любое исправление протокола приходилось вносить в трёх местах. Текущая версия сжимает всё в один файл с одной таблицей: поиск устройства, каналы доставки, CLI и `POLLING_VARIANTS` — единственное место в кодовой базе, где живут байты протокола. Добавить ещё одну частоту, если её когда-нибудь удастся перехватить, — значит добавить одну строку в таблицу.

## Дисклеймер

Неофициальный проект по реверс-инжинирингу. Не аффилирован с CompX, Ardor Gaming, Areson Technology или их дистрибьюторами и не одобрен ими. Протокол получен экспериментальным путём; использование — на ваш страх и риск; инструмент поставляется без каких-либо гарантий.
