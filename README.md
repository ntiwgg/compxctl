# compxctl

**Частота опроса и DPI для мышей CompX / Ardor Gaming в Linux — без фирменной утилиты для Windows.**

CLI из одного Python-файла. Делает две вещи, которые живут в совершенно разных местах, и намеренно их не смешивает:

| Что | Где живёт | Как это делает compxctl | Нужны пакеты |
|---|---|---|---|
| Частота опроса | в цикле опроса USB на стороне хоста | `usbhid.mousepoll` + дескриптор эндпоинта в sysfs | **никаких** (только stdlib) |
| DPI, батарея, конфиг-память | внутри чипа мыши | проприетарный HID-протокол через raw USB | `pyusb` |

```console
$ compxctl rate
Device: 2.4G Dual Mode Mouse (25a7:fa7b)
Device advertises: 1000 Hz (1ms via interval, ep_81)
Host override: none (usbhid.mousepoll = 0)
Effective: 1000 Hz (from device descriptor)
```

## Зачем это и почему переписано

Первая версия меняла частоту опроса записью в EEPROM мыши через реверс-инжиниренный протокол. Это работает — проверено на железе, — но это самый хрупкий и наименее переносимый способ: необратимо, ограничено ресурсом записи, неприменимо к другой мыши и завязано на одну пойманную прошивку.

Linux и так отдаёт частоту опроса нормально. Хост опрашивает interrupt-эндпоинт с интервалом, который объявляет устройство, а `usbhid` умеет этот интервал переопределить для всех мышей сразу. Поэтому:

* **Чтение частоты** — это чтение sysfs: точно, мгновенно, без движения мыши, без подсчёта событий, без зависимостей. Прежний `check` полторы секунды считал события ввода и показывал примерно вдвое больше реального, стоило двинуть мышь по диагонали: один отчёт мыши несёт и `REL_X`, и `REL_Y`, а счётчик считал оба. Команда удалена, её место занял `rate`.
* **Установка частоты на хосте** — одна запись в `/sys/module/usbhid/parameters/mousepoll`. Обратимо, без EEPROM, без вендорского протокола.
* **Запись интервала в устройство** осталась, потому что это единственный способ изменить то, что мышь объявляет *любому* хосту (включая Windows), но теперь это явный opt-in за `--persist`.

## Установка

```console
$ pip install pyusb     # только для dpi / status / battery / probe / rate device
```

Это весь список зависимостей. `rate` и `--version` работают на голом Python 3.10+ без ничего.

Можно поставить и как пакет:

```console
$ pip install .            # только CLI, без зависимостей
$ pip install ".[device]"  # + pyusb для команд устройства
```

## Использование

### Частота опроса

```console
$ compxctl rate                 # показать: устройство, переопределение хоста, итог
$ sudo compxctl rate host 1000  # на стороне хоста, для всех USB-мышей, обратимо
$ compxctl rate device 1000 --persist      # плюс запись в EEPROM мыши
```

`rate host` пишет `usbhid.mousepoll`, а это действует на **все USB-мыши** в системе. Настройка не переживает перезагрузку, и способ сделать её постоянной зависит от того, как собран `usbhid` — команда сама печатает нужную строку:

* **загружаемый модуль** — `options usbhid mousepoll=1` в `/etc/modprobe.d/`
* **встроен в ядро** — `usbhid.mousepoll=1` в командной строке ядра, потому что `/etc/modprobe.d/` для встроенных модулей молча игнорируется

Инструмент определяет случай сам (`usbhid_is_builtin()` читает `/lib/modules/$(uname -r)/modules.builtin`). Это не гипотетика: на машине, где это писалось, `usbhid` встроен, и лежавший в `/etc/modprobe.d/mousepoll.conf` файл не делал ровно ничего.

`rate device HZ --persist` шлёт два «живых» пакета интервала и один кадр записи в EEPROM, затем читает значение назад:

```console
$ compxctl rate device 1000 --persist
Device EEPROM updated to 1000 Hz (0x01).
  Re-plug the mouse (or replug the receiver) for the host to re-read it.
```

Без `--persist` команда отказывается работать, а если в устройстве уже лежит нужное значение — не пишет вообще ничего.

Что выбрать:

* **«Хочу 1000 Гц в Linux прямо сейчас»** → `rate host 1000`. В мышь не пишется ничего.
* **«Настройка должна ехать вместе с мышью»** → `rate device 1000 --persist`.
* **«Хочу 125/500 Гц»** → лучше путь через устройство: если заставить хост опрашивать раз в 8 мс, это замедлит **все** мыши, включая 1000-герцовую.

### DPI

```console
$ compxctl dpi list
  slot  addr    x    y    mul  crc   value
  *0   0x000C  07   07   00   47    400
   1   0x0010  13   13   00   2F    1000
   2   0x0014  1F   1F   00   17    1600
   3   0x0018  2F   2F   00   F7    2400
   4   0x001C  77   77   00   67    6000
   5   0x0020  7F   7F   00   57    6400
   6   0x0024  EF   EF   00   77    raw:0xEF
   7   0x0028  7B   7B   44   1B    raw:0x7B(mul=0x44)
Active DPI level: slot 0 (index 0x01)

$ compxctl dpi 2400              # записать в слот активного уровня
$ compxctl dpi --slot 3 2400     # записать в явный слот 0..5
```

Хранится не само значение, а код: `DPI / 50 - 1`, поэтому DPI должен быть кратен 50 в диапазоне 50..6400. Каждая запись проверяется чтением **всех четырёх байт** назад.

Слоты 6 и 7 на проверенном экземпляре держат нерасшифрованную расширенную кодировку: они показываются сырыми байтами и никогда не перезаписываются. Если регистр активного уровня (`0x0004`) не содержит корректного индекса 1..8, `dpi N` отказывается угадывать и просит `--slot` — прежняя версия в этом случае молча писала в слот 0.

### Остальное

```console
$ compxctl status
Device: 2.4G Dual Mode Mouse (25a7:fa7b)
Device advertises: 1000 Hz (1ms via interval, ep_81)
Host override: none (usbhid.mousepoll = 0)
Effective: 1000 Hz (from device descriptor)
Stored rate: 1000 Hz (config memory 0x0000)
Active DPI level: index 0x01 (0x0004) -> slot [0]: 400
DPI slots: [0] 400 <- active [1] 1000 [2] 1600 [3] 2400 [4] 6000 [5] 6400 [6] raw:0xEF [7] raw:0x7B(mul=0x44)
Battery: 100% (not charging) [2.4G mode]

$ compxctl battery
Battery: 100% (not charging) [2.4G mode]

$ compxctl probe --start 0x0000 --length 0x20
0x0000: 01 54 05 50 01 54 00 55
0x0008: 00 55 01 54 07 07 00 47
0x0010: 13 13 00 2f 1f 1f 00 17
0x0018: 2f 2f 00 f7 77 77 00 67
Interpretation:
  0x0000 stores the interval code 0x01 = 1000 Hz
  slot 0: 07 07 00 47 (checksum OK)
  ...
```

`status` сопоставляет то, что объявляет устройство (`1ms`), с тем, что лежит в его EEPROM (`0x0000`), — если они разойдутся, это будет видно.

## Права доступа

* `rate` на чтение не требует ничего.
* `rate host` требует root — это запись в параметр модуля ядра.
* Командам устройства нужен доступ к USB-узлу. Проще всего поставить udev-правило из репозитория:

```console
$ sudo cp 99-compx-mouse.rules /etc/udev/rules.d/
$ sudo udevadm control --reload-rules && sudo udevadm trigger
```

```udev
SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTRS{idVendor}=="25a7", TAG+="uaccess"
```

`TAG+="uaccess"` покрывает активную сессию logind. Разово можно просто `sudo`. Учтите: `GROUP="users"` как запасной вариант — ловушка переносимости, этой группы нет в Fedora и Arch, и правило тогда молча ничего не даёт.

## Поддерживаемые устройства

USB vendor `0x25A7`, product id `0xFA7B`, `0xFA7C`, `0xFA03`, `0xFA93`. Протокол перехвачен и проверен на Ardor Gaming Ulta (PID `0xFA7B`); соседние id обслуживаются тем же кодом, но по отдельности не проверялись.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | ошибка выполнения — нет устройства, нет прав, плохой ответ, отказ проверки чтением назад |
| `2` | ошибка аргументов командной строки (argparse) |
| `130` | прервано по Ctrl+C |

## Тесты

```console
$ pip install pytest && pytest
```

114 тестов, которым не нужны ни железо, ни root, ни `pyusb`: слой устройства работает через поддельный pyusb, слой sysfs — через синтетическое дерево. Отдельно зафиксированы две настоящие ошибки, найденные при ревью прошлой версии: разбор hex-атрибутов USB-дескриптора и частичная проверка readback у DPI (принимала неверный `y`).

## Ограничения

* Путь через EEPROM по-прежнему реверс-инжинирен и по-прежнему ограничен ресурсом записи. `--persist` — единственная команда, которая туда пишет, и она проверяет результат чтением назад и сверяет кадр с проверенным на железе захватом.
* `rate host` не умеет «только эту мышь» — `mousepoll` глобальный.
* Слоты 6-7 используют нерасшифрованную кодировку и не перезаписываются.
* `status`, `battery`, `probe` требуют `pyusb`; запасного пути через hidraw нет, потому что конфиг-интерфейс этой мыши занят `usbhid`.
