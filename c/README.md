# compxctl C / CLI + TUI

Новая самостоятельная реализация на **C17 для Linux**. Один бинарник, без Python,
ncurses и сторонних библиотек при запуске. Версия **5.0.0-dev**: код и интерфейс
проверяются автоматически; приёмка новой реализации на физической мыши ещё нужна.

## Сборка и запуск

```sh
make
./build/compxctl tui --demo
./build/compxctl devices
./build/compxctl tui
```

Нужны C-компилятор, make и Linux development headers. Для тестов дополнительно
нужен Python 3 со стандартной библиотекой. Никаких pip-пакетов.

`--demo` использует отдельную модель устройства в памяти. Ни sysfs, ни hidraw,
ни USB не изменяются. Изменения симулятора живут до завершения процесса.

## Возможности

| Возможность | CLI | TUI |
|---|---|---|
| Список и явный выбор приёмника | `devices`, `--device 3-2` | 5 Devices |
| Батарея, зарядка, активный уровень | `status`, `battery` | 1 Overview |
| Восемь слотов DPI, байты и контрольные суммы | `dpi list` | 2 DPI |
| Запись неактивных слотов 0..5 | `dpi set 1 1600 --confirm` | выбрать слот, e, значение, y |
| Параметр интервала на хосте | `rate host 500 --confirm` | 3 Intervals, h |
| Экспериментальный код интервала | `rate device 500 --persist --confirm` | 3 Intervals, s |
| Чтение конфиг-памяти | `probe --start 0 --length 64` | 4 Diagnostics, a / p |
| Явный сброс всего приёмника | `reset --confirm` | 4 Diagnostics, x |
| Границы поддержки | `capabilities` | 6 Help |

RGB, переназначение кнопок, макросы, debounce и lift-off distance **не реализованы**:
для них нет достаточного подтверждённого протокола. Наличие этих функций у каждой
модели также не установлено. Экспериментальные live-пакеты старой программы не
исполняются на железе: измеримого эффекта у проверенного экземпляра не показано.

Поддерживаемые USB ID: `25a7:fa7b`, `fa7c`, `fa03`, `fa93`. Протокол исходного
проекта снимался на `fa7b`; новая C-реализация пока не проверялась на физическом
устройстве. Запись разрешена только для `fa7b`, остальные PID доступны на чтение.

## Интерфейс

Минимум 80x24, ANSI-совместимый терминал. 1..6 / Tab переключают экраны,
стрелки или j/k выбирают строку, r обновляет данные, q выходит. На обзоре, DPI
и интервалах состояние обновляется каждые 3 секунды. Ошибка чтения убирает старое
значение: неизвестное не показывается как актуальное.

Изменения не отправляются до отдельного подтверждения y. Переход между экранами
ничего не записывает. При SIGINT/SIGTERM восстанавливаются режим терминала,
курсор и основной экран. SIGKILL восстановить средствами процесса невозможно.

## Гарантии и ограничения

- Дескриптор, параметр хоста и измерение — разные данные. Поля «эффективная
  частота» нет; `measured_rate_hz` остаётся `null`.
- `rate host` меняет глобальный параметр. Для применения переподключите затронутые
  мыши; успешная запись не доказывает изменение частоты уже подключённого
  устройства. Соответствие 1/2/8 → 1000/500/125 относится к full-speed USB.
  High-speed endpoint использует другую кодировку. Учитывайте другие USB-мыши.
- `rate host 0 --confirm` убирает переопределение; применение тоже требует
  переподключения. Параметр не сохраняется после перезагрузки.
- Запись интервала устройства подтверждает два байта, а не изменение частоты.
  Сохранение после выключения не проверено. Live-пакеты не подмешиваются к записи.
- DPI: проверяются четыре байта. Активный уровень проверяется дважды; неизвестный
  или повреждённый индекс блокирует запись. Не нажимайте физическую кнопку DPI
  во время изменения: программная блокировка не может заблокировать эту кнопку.
- Слоты 6..7 не перезаписываются. Несимметричные X/Y декодируются раздельно;
  данные с неверной контрольной суммой не выдаются за достоверный DPI.
- Запись не повторяется автоматически. Ошибка после отправки означает возможное
  изменение состояния. JSON сохраняет `write_attempted` и `readback_verified`;
  при ошибке после попытки записи без подтверждения `changed` равен `null`.
- Чтение ограничено абсолютным сроком ожидания. Очистка очереди использует
  настоящую нулевую проверку готовности и прекращается при бесконечном потоке.
  Истечение `--timeout-ms` относится к ожиданию ответа, не к времени kernel ioctl.
- Блокировка сериализует экземпляры compxctl. Она совместима с flock Python-версии.
  Чужие программы и физические кнопки она не блокирует.
- В протоколе нет номера запроса. Отложенный ответ с тем же заголовком остаётся
  неотличимым от свежего. Очистка очереди уменьшает риск, но не доказывает свежесть.
- `reset` сообщает принятие запроса, не обещает успешное возвращение приёмника,
  перезапуск драйвера или применение mousepoll. Проверяйте повторным `devices/status`.
- При нескольких приёмниках автоматического выбора первого нет.

## Права и установка

```sh
make install PREFIX="$HOME/.local"
```

Это устанавливает бинарник и man-страницу. Не перезаписывайте существующую команду
в том же prefix без резервной копии; для параллельной проверки используйте
`./build/compxctl`.

Для команд устройства в активной desktop-сессии logind установите
`udev/70-compx-mouse.rules` в `/etc/udev/rules.d/`, затем перезагрузите правила и
переподключите приёмник. Перед заменой существующего файла сохраните его копию.
Правило должно идти **раньше** стандартного `73-seat-late.rules`.

Если осталось старое `99-compx-mouse.rules`, сначала изучите его: оно могло быть
изменено вручную. Уберите старые широкие разрешения после переноса необходимых
настроек. Новая установка ничего автоматически не удаляет.

Для `reset` отдельно установите `udev/70-compx-reset.rules.optional` как
`/etc/udev/rules.d/70-compx-reset.rules`. Оно даёт доступ ко всему USB-приёмнику;
для DPI/батареи/чтения это разрешение не нужно. Параметр хоста требует root.
Не делайте бинарник setuid. По SSH без активной logind-сессии uaccess не поможет.

## JSON и совместимость

Schema **3**, намеренно несовместимая с прежним вычисленным `effective_rate_hz`.
`status`, `rate` без аргументов и `dpi list` возвращают общий документ с
`command: "status"`, снимком состояния, `null` для неизвестного и `warnings`.
`battery` читает только батарею. Вывод ошибок — один документ, если выбран `--json`.
Коды: 0 — успех (в снимке могут быть предупреждения), 1 — отказ операции,
2 — неправильная команда, 130 — SIGINT, 143 — SIGTERM.

`dpi set` заменяет прежний `dpi --slot`; все CLI-изменения требуют `--confirm`.
Комбинированного `rate both` нет: host/device — независимые операции с разными
правами и условиями применения. Нельзя молча оставить половину команды выполненной.

## Архитектура

| Файл | Ответственность |
|---|---|
| `src/protocol.c` | кадры, границы, HID globals PUSH/POP, запросы и сроки |
| `src/linux.c` | sysfs, hidraw, poll/ioctl/flock, идентификация, симулятор |
| `src/device.c` | чтение состояния, ограничения и проверка операций |
| `src/output.c` | текст и JSON |
| `src/main.c` | CLI и проверки аргументов |
| `src/tui.c` | терминал, страницы, ввод и подтверждения |

TUI и CLI используют одни операции. Нет команды произвольной записи памяти,
нет фонового демона, автоматического sudo, сетевых запросов или внешних процессов.

## Проверки

```sh
make test
make sanitize
```

Тесты ядра проверяют реальные неблокирующие сокеты, очистку старых ответов,
подтверждения записи, таймауты и неисправные кадры. Тесты операций покрывают
неизвестный/сменившийся активный уровень, неизменённый слот, несовпадение readback,
неизвестный результат записи и ограничения sibling PID. Разбор дескрипторов
прогоняется на 20 000 детерминированных случайных образцов под ASan/UBSan.
Это ограниченная проверка устойчивости, а не исчерпывающий фаззинг.

CLI проверяется как отдельный процесс. TUI проверяется в настоящем PTY:
редактирование, подтверждение, отмена, страницы, дамп, уменьшение терминала,
SIGTERM/SIGINT, восстановление termios. Деморежим не доказывает работу на железе.

## Приёмка на мыши перед релизом

1. Сравнить read-only `status`, `battery`, `probe` с прежней версией и захватами.
2. Проверить обычного пользователя на чистом правиле udev, затем подключение,
   сон/пробуждение и извлечение приёмника во время ожидания.
3. Сохранить полный дамп, записать один неактивный DPI-слот, проверить все байты
   и отсутствие изменений вне него. Проверить сохранение после выключения.
4. Проверить параллельные экземпляры и смешанный запуск Python/C.
5. Проверить host-параметр до/после переподключения независимым измерением.
6. Если нужен reset — отдельно проверить клавиатуру на том же приёмнике.

Только после этих проверок можно обозначать C-версию как проверенную на устройстве.
